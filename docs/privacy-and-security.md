# Privacy and Security

## Public repository guarantee

This repository should contain only generic methods, fictional examples, and empty templates. It must not contain:

- real names or contact details;
- private chat excerpts or meeting transcripts;
- internal URLs, hostnames, project identifiers, or organization charts;
- credentials, cookies, API keys, or tokens;
- unreleased metrics, strategy, financial data, or customer information;
- screenshots of private work systems.

## User responsibility

Before using the prompt, check your organization’s policy and the data policy of the AI provider. When unsure, replace real content with neutral placeholders or use an approved local environment.

## Human confirmation gates

AI may propose but should not independently finalize:

- formal owners and deadlines;
- external messages or calendar writes;
- financial, legal, compliance, hiring, or access decisions;
- deletion, publication, or irreversible actions;
- task completion when acceptance evidence is ambiguous.

## Threat model

This documentation-first release executes no code and stores no credentials. Risk enters when users connect external systems or paste sensitive content. Future integrations should be opt-in, least-privilege, auditable, and disabled by default.

## Reporting a problem

Open a GitHub issue without including sensitive evidence. If the report itself contains private data, do not post it publicly.
